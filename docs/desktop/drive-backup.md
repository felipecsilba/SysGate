# Krakion App — Google Drive e backup

Parte da documentação do Krakion App. Índice e "Retomar aqui": `docs/desktop.md`.

## Conexões → Google Drive (botão de plugue no rodapé do Rail, 2026-10-19)

Tela: botão de plugue no rodapé do Rail, acima do tema (grupo `conexoes` com `rodape: true` no `modulos.js`). `/conexoes` = lista no estilo das telas de conectores (busca + uma linha por serviço; catálogo em `src/lib/conexoes.js`, com Claude API e Gmail como "Em breve"). Clicar abre `/conexoes/<id>`: no Google Drive, um passo a passo em 3 etapas (criar app no Google Cloud → colar credenciais → conectar) enquanto não está conectado, e depois os dados da conexão com Testar/Desconectar. Primeiro conector (opção B do brainstorming: OAuth próprio + API REST, sem dependência nova). Plano: `docs/plans/2026-10-19-desktop-conexao-google-drive.md`. Configuração do Google Cloud (passo a passo do Felipe): `docs/conexoes-google-drive.md`.
- `electron/conexoes/googleDrive/oauth.js`: PKCE, URL de autorização, servidor de retorno em `127.0.0.1:<porta livre>` (confere `state`, tempo limite de 5 min, cancelável), troca de código, renovação, revogação.
- `cliente.js`: `sobre`, `garantirPasta`, `enviar` (upload resumable em partes de 8 MB, lê o arquivo do disco em partes; serve o backup grande), `baixarTexto`, `excluir`. Num 401 renova o acesso e repete uma vez.
- `index.js` (`criarConexaoDrive`): `<userData>/google-drive.json` com client ID, segredo **cifrado**, refresh token **cifrado**, conta, pasta, datas; o acesso curto fica só na memória. Cifra injetada (`safeStorage` no `main.js`) para os testes rodarem no Node. `invalid_grant` → marca desconectado e pede para conectar de novo. Trocar o client ID derruba a conexão.
- Escopo **`drive.file`**: o app só enxerga o que criou (pasta **Krakion App**). O app OAuth precisa estar **Em produção** no Google Cloud (em Teste o refresh token expira em 7 dias).
- IPC `drive:*` (via `comErro`) + `window.krakion.drive`. A URL da pasta para "Abrir no Drive" sai do status guardado, nunca da tela.
- Testes: `oauth.test.js` (8), `cliente.test.js` (5) e `index.test.js` (11) contra `googleFalso.js` (OAuth + Drive falsos em memória; `KRAKION_GOOGLE_BASE` aponta o app para ele). `safeStorage` real conferido num smoke dentro do Electron.
- **Conectado no Google de verdade em 2026-10-20** (conta do Felipe; projeto `Krakion App` no Google Cloud, app OAuth **Em produção**, cliente "App para computador"). Para publicar, o Google exigiu página inicial + política de privacidade: `https://krakionlabs.cloud` e `https://krakionlabs.cloud/privacidade.html` (arquivo estático `frontend/public/privacidade.html`, no `master`). Sem logo no Branding (logo obrigaria verificação). Cliente sem a opção "AI-powered agent" — agentes futuros usam um cliente separado.

## Backup no Google Drive (Conexões → Google Drive → cartão Backup, 2026-10-20)

Plano: `docs/plans/2026-10-20-desktop-backup-drive.md`. Módulos em `electron/backup/`:
- **Banco, todo backup:** `exportarBanco.js` exporta todas as tabelas do schema public para JSON compactado (`banco-AAAA-MM-DD_HHMMSS.json.gz`), lendo com `pg`. O Postgres embutido **não traz `pg_dump`**. No banco real: 30 tabelas, 352 KB, 0,2 s. Guarda **30**.
- **Biblioteca, só o que mudou:** um zip por pasta principal de `biblioteca/` (mais `_raiz` para os arquivos soltos). `impressao.js` (caminho + tamanho + data, sem ler conteúdo; ignora `__pycache__`) fica em `<userData>/backup.json` e é gravada logo depois de cada pasta subir, então uma falha no meio não reenvia o que já foi. Guarda **3** versões por pasta.
- `zip.js`: zip próprio, sem dependência (deflate, nomes UTF-8, prefixo `\\?\` para caminhos longos, limites sem zip64 checados). Conferido com o `zipfile` do Python na biblioteca real: Relatorios (8.717 arquivos, 146 → 30 MB em ~5 s), `_RASCUNHOS-TESTES` (caminhos > 260) e Formulas byte a byte.
- `retencao.js`: carimbo **com segundos** (o automático e o manual no mesmo minuto geravam nomes iguais) e "manter os N mais recentes por grupo"; arquivos fora do padrão nunca são apagados.
- `index.js` (`criarBackup`): `status`, `precisaRodar` (conectado e último sucesso há mais de 24 h), `executar` (uma execução por vez, progresso por etapa, temporários sempre apagados). No Drive: `Krakion App/Backups/Banco` e `Krakion App/Backups/Biblioteca`.
- `main.js`: checa 15 s depois de abrir e a cada hora; IPC `backup:status`/`backup:executar` + eventos `backup:progresso`/`backup:fim`; log `[backup]` no `krakion.log`.
- **Sem segredos (decisão do Felipe, 2026-10-20):** tokens e senhas se pegam de novo, então não vão para o backup. `exportarBanco` omite toda coluna com `senha|token|secret|segredo|password` no nome (hoje: `MunicipioSistema.token`, `senhaHash` e `recuperacaoToken[Hash]` de `Usuario`/`Solicitante`) e mascara cabeçalhos de autorização em `Requisicao.headers`. O JSON (`krakion-banco-v2`) lista o que foi omitido em `omitidos`. Conferido no banco real: 4 tokens + 1 hash, nenhum no backup. Uma vez só (`bancoSemSegredos` no `backup.json`), o primeiro backup depois da mudança apagou do Drive os backups de banco antigos, que tinham segredos. Ao restaurar no futuro: criar a senha local de novo e renovar os tokens (Central de Tokens / agente do Betha Admin). Restaurar pelo App fica para depois.
